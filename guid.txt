# PART A — GitHub Actions CI Pipeline

## What are we actually trying to achieve?

Imagine you have a website:

```text
index.html
```

Every time you change the code and push it to GitHub, you want GitHub to automatically perform some tasks.

Instead of you manually saying:

> "Check my code."

GitHub Actions automatically says:

> "A new change was pushed. I'll run the CI workflow."

Our workflow will:

```text
Developer pushes code
        ↓
GitHub detects push
        ↓
GitHub Actions starts
        ↓
Checkout code
        ↓
Display "Build Started"
        ↓
List project files
        ↓
Display "Build Completed Successfully"
        ↓
SUCCESS ✅
```

This is the basic idea of **Continuous Integration**.

# Step 11 — Open `ci.yml`

In VS Code Explorer, find:

```text

└── workflows
    └── ci.yml
```

Click `ci.yml`.

Paste this:

```yaml
name: GitHub CI Pipeline

on:
  push:
    branches:
      - main

jobs:
  build:
    runs-on: ubuntu-latest

    steps:
      - name: Checkout Repository
        uses: actions/checkout@v4

      - name: Display Message
        run: echo "Build Started"

      - name: List Files
        run: ls

      - name: Build Successful
        run: echo "Build Completed Successfully"
```

Save:

**Ctrl + S**

# Step 12 — Understand the workflow



# Step 42 — Enter the Pipeline script

Paste this:

```groovy
pipeline {
    agent any

    stages {
        stage('Checkout') {
            steps {
                echo 'Checking out source code...'
            }
        }

        stage('Build') {
            steps {
                bat 'echo Building Project...'
            }
        }

        stage('Test') {
            steps {
                bat 'echo Running Tests...'
            }
        }

        stage('Deploy') {
            steps {
                bat 'echo Deployment Successful'
            }
        }
    }
}
```

Save the project.

This is called a **Jenkinsfile-style Declarative Pipeline script**.

It has four stages:

```text
Checkout
   ↓
Build
   ↓
Test
   ↓
Deploy
```

```groovy
stage('Checkout')
```

This represents obtaining source code.

In our simple lab script, it only prints:

```text
Checking out source code...
```

It does not actually clone GitHub because the experiment's pipeline script is demonstrating stages.

---

### Build

```groovy
stage('Build')
```

It runs:

```text
Building Project...
```

---

### Test

```groovy
stage('Test')
```

It runs:

```text
Running Tests...
```

---

### Deploy

```groovy
stage('Deploy')
```

It runs:

```text
Deployment Successful
```

So the conceptual pipeline is:

```text
┌──────────┐
│ Checkout │
└────┬─────┘
     ↓
┌──────────┐
│  Build   │
└────┬─────┘
     ↓
┌──────────┐
│   Test   │
└────┬─────┘
     ↓
┌──────────┐
```

# Important viva questions to learn

### 1. What is CI?

**Continuous Integration** is the practice of automatically building and testing code whenever developers integrate changes into a shared repository.

### 2. What is Jenkins?

Jenkins is an open-source automation server used to automate software development tasks such as building, testing, and deployment.

### 3. What is GitHub Actions?

GitHub Actions is GitHub's built-in automation platform for running workflows in response to repository events such as pushes.

### 4. What is a workflow?

A workflow is a YAML file containing instructions that GitHub Actions executes automatically.

In our experiment:

```text
.github/workflows/ci.yml
```

is the workflow file.

### 5. What triggers our GitHub Actions workflow?

This:

```yaml
on:
  push:
    branches:
      - main
```

means a push to the `main` branch triggers the workflow.

### 6. What is `runs-on: ubuntu-latest`?

It tells GitHub Actions to execute the job on a GitHub-hosted Ubuntu runner.

### 7. What is a Jenkins Freestyle project?

It is a Jenkins job where configuration such as source control and build steps is primarily configured through the Jenkins web interface.

### 8. What is a Jenkins Pipeline?

A Jenkins Pipeline defines the CI/CD process as code, using stages such as:

```text
Checkout → Build → Test → Deploy
```

### 9. What does `Finished: SUCCESS` mean?

It means the Jenkins build completed successfully without an error.

### 10. What is the main advantage of CI?

CI reduces manual work and gives developers fast feedback when code changes introduce problems.

## One important correction to your lab manual

There is a subtle difference between the **conceptual objective** and the exact Jenkins Pipeline script your manual gives you.

The Pipeline script:

```groovy
stage('Checkout') {
    steps {
        echo 'Checking out source code...'
    }
}
```

**doesn't actually check out GitHub code**. It only prints a message saying that checkout is happening.

Likewise:

```groovy
bat 'echo Running Tests...'
```

doesn't actually run tests—it only prints the message.

That's **fine for this particular introductory experiment** because the goal is to demonstrate Jenkins Pipeline stages. Just don't claim in your viva that this particular script actually downloaded, built, tested, and deployed a real application. It demonstrates those **pipeline stages**.
